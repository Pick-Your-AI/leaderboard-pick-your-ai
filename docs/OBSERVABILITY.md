# Operational telemetry and alert boundary

`infra/observability/monitor.mjs` records a fixed allowlist of stages, known failure codes, bounded trace/revision IDs and measured latency. Source identifiers are hashed; account names, URLs, payloads, exception strings and credentials are excluded. Retention, freshness and alert cooldown budgets must be provided explicitly. Telemetry/source/alert cardinality and concurrent destination calls are bounded.

Successful collection polls update freshness even when no new contribution occurs. Quiet activity alone never sends an alert. A source failure generates a fixed actionable message with trace and last-known revision context; `status` reflects the same recorded success/failure state. Unknown sources or expired telemetry remain unknown, rather than healthy by default. Inject this monitor at actual collection/publication/recovery boundaries; a UI screenshot is not collection evidence.

An approved destination adapter must acknowledge a receipt before delivery is reported. Missing, failed, unacknowledged or saturated destinations produce explicit undelivered states. Concurrent duplicate failures coalesce, successful alerts are rate-limited by source/code, and failures do not falsely mark later attempts delivered. Destination adapters must bound their network request duration; a noncooperative hanging adapter consumes a bounded pending slot rather than launching unbounded retries. No email, chat, webhook or operating commitment is selected or contacted by this module.

An in-flight source/code and its subsequent acknowledged cooldown occupy one shared capacity slot. When all slots are reserved, a new identity returns `undelivered` with `destination_capacity_exceeded`; active cooldowns remain intact. Expired cooldowns free their own slots, and failed or unacknowledged attempts release their reservations. Pending calls retain their slots until they settle, even if telemetry retention expires. The cooldown starts when the destination acknowledges delivery. Failure telemetry and source health are recorded before admission, including when alert capacity is exhausted.

Run `node --test infra/observability/test/*.test.mjs`. Synthetic failure injection verifies an actionable acknowledged alert, matching health, redaction, retry/coalescing, rate limiting, retention and no-activity behavior.
