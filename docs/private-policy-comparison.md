# Private frozen-policy comparison candidate

Refs [#115](https://github.com/Pick-Your-AI/pick-your-ai-leaderboard/issues/115), [#122](https://github.com/Pick-Your-AI/pick-your-ai-leaderboard/issues/122) and optional investigation of [#83](https://github.com/Pick-Your-AI/pick-your-ai-leaderboard/issues/83). This bounded executable preview is partial implementation evidence. It does not satisfy designated policy approval, a public policy release, published release notes, a rollout/rollback drill, source capability approval or deployment acceptance.

## Durable input and replay

The authorized pipeline captures its minimum normalized metric-engine input, exact scope, baseline policies, and baseline aggregate inclusion evidence and exclusion audit in private SQLite tables when the existing controls transaction confirms a SQL publication. Each retained input is bound to the immutable snapshot ID/revision, configuration hash, controls configuration revision, source generations, data mode and known correction hashes. No raw GitHub payload, OAuth credential, request body or source-provider secret is included. Engine actor records omit provider transport metadata.

The frozen-record ID and input, scope, policy, baseline and result hashes use SHA-256 over stable canonical JSON. Approved baseline and unapproved candidate metric/version hash bindings have separate permanent local registries and independent bounds. A candidate cannot reserve an approved version or consume approved capture capacity. Changed candidate semantics under the same version are rejected, including after retained inputs expire. An exact approved binding takes precedence over an earlier conflicting candidate binding, so unchanged-baseline inspection remains available. A conflicting approved binding makes optional capture unavailable; it cannot veto an independently approved publication. A content-addressed retry does not refresh input expiry or authorization. A new preview checks that recalculating the baseline still matches its persisted result; changed engine behavior requires a newly captured input. An already saved comparison replays its exact result hash across restart while its retained source coverage still supports any complete claim.

Cached GET and POST responses recheck complete before/after aggregates against their retained input coverage and each policy's required sources. This source-only check runs synchronously inside the existing source, identity and session fence, with the host's frozen identity restoration when supplied. Missing or short reconciled watermarks return 409 `Frozen preview source coverage changed`; the old input, result and digest remain unchanged. Valid partial and complete previews retain exact cached values, evidence and ranks without another aggregate calculation. The check introduces no new stored schema, policy version or snapshot identity and does not turn a private preview into public recognition.

Both policies run through `comparePolicies` on the identical retained input and scope. The response preserves independent values, ranks, inclusion/exclusion IDs, engine audit causes, and changed policy fields. `beforeRank`/`afterRank` are candidate recalculation differences, not comparable historical live movement. Unknown and partial coverage retain engine semantics. An excluded correction is evidenced by the engine audit rather than silently erased from the original input.

## Protected HTTP contract

Pipeline `start({ controls: ... })` supplies the actual metric engine and current source guard to `createControlsServer`. Standalone controls servers without this integration return 503 for the preview namespace.

- `GET /controls/policy-comparisons/inputs`: bounded metadata list, snapshot binding, expiry and baseline policy hashes; no input facts or internal audit.
- `POST /controls/policy-comparisons`: JSON `{ "inputId": "<retained-record-hash>", "candidatePolicy": { ...complete metric policy... } }`. The baseline is selected by the candidate metric ID from the retained record. The server does not accept caller-supplied facts, source authorizations, scopes, approvals or baseline policies.
- `GET /controls/policy-comparisons/<comparisonId>`: re-read a saved private comparison with current authorization and privacy checks.

All routes require the current `reviewer` role; an operator role alone is insufficient. Mutation uses the existing same-origin, CSRF, JSON size, session expiry and role-version checks. Reviewer authority is refreshed after awaited source checks, then configuration approval is refreshed again. After both awaits, a combined synchronous authority fence inside the final controls transaction checks the exact current approved configuration and reviewer role version. This closes revocation windows in either awaited refresh. That transaction also verifies the still-active session and controls configuration, computes/persists the preview, and applies current privacy. Authority, session and retained-input expiry are rechecked after calculation/redaction before commit, so work crossing a deadline rolls back its preview and candidate bindings. A final check after commit and again after HTTP serialization withholds any response whose authority has expired before headers are written. Source read locks remain held through the HTTP response. Suppression and correction writers use the matching exclusive source gate. Lock order is PostgreSQL repository rows in repository-ID order, then the synchronous SQLite controls transaction; no SQLite transaction awaits PostgreSQL. Normalizer suppression starts a separate exclusive-gate transaction before publication, with no shared-to-exclusive lock upgrade. Private failure messages are bounded and do not echo provider exceptions or source payloads.

Current source revocation/generation changes, unapproved configuration or changed controls configuration fail closed, even for saved results. A current contributor suppression or removed artifact withholds affected rows, change records and audit identifiers. Ranks are withheld when redaction changes the visible result. A newly applied correction redacts historical input until a new frozen record evaluates that exact correction. Trusted correction hashes are derived from reviewed revisions observed by the frozen cutoff that the baseline engine audit actually excludes; a correction merely present after the cutoff cannot authorize disclosure of the original fact. Inclusion/exclusion causes use the same cutoff and reviewed-revision eligibility as the engine. `resultHash` authenticates the stored immutable result; `responseHash` authenticates the currently redacted response, with `redactionsApplied` explicit. Privacy redaction does not rewrite a historical frozen input or authorize its reuse.

Every response is `candidate_preview`, with `publicEnabled: false`, `activationSupported: false`, and approval/release-note requirements explicit. There is no approve, activate, release or rollback mutation in this namespace. Existing approved configuration and public projections are untouched. `/controls/public`, board, contributor, export and public methodology APIs do not expose these private records, audit IDs or hashes. A reviewer can preview the unchanged baseline to inspect its stored calculation/audit without granting it new authority.

## Final authority fence host contract

`createPipeline` accepts `policyComparisonAuthorityCurrent({ configurationHash, actorId, roleVersion })`. It must synchronously return exactly `true` only when both the exact configuration and reviewer role version remain authoritative. A missing callback, stale/absent authority, `false`, or any thenable fails closed before a private result is saved or sent. The callback runs while repository read locks and the synchronous controls transaction are held; it must not await, acquire PostgreSQL locks, or infer approval from a successful earlier request.

`createPolicyPreviewAuthority` in `apps/controls/src/policy-preview-authority.mjs` provides an executable versioned local authority cache. It starts empty. Its `replace` method accepts only `policy-preview-authority/v1`, a strictly advancing revision, at most 100 approved configuration hashes, at most 10,000 exact actor/role-version bindings, and a validity deadline no more than 60 seconds ahead. Its synchronous `isCurrent` method can supply the pipeline callback. The host must populate this cache from its actual approval and roster administration and replace it synchronously as part of every authoritative revocation; an eventually consistent mirror of an independent authority is insufficient. Expiry is a fail-closed bound, not permission to delay revocation. Process restart starts empty again.

There is no production default approval or synthetic fallback. Existing independent configuration/source approval and reviewer authentication checks remain required. Deployment wiring to a designated real approval authority is still an acceptance dependency; synthetic tests demonstrate the executable cache contract without creating real approval evidence.

## Local v1 resource and retention limits

These versioned implementation defaults are local test/runtime guardrails, not an accepted production retention promise:

- Seven-day retention for frozen records and their previews; expiry is not extended by replay
- At most eight retained frozen records, 10,000 facts and 2,000 actors per record
- At most 98 baseline policies and 2 MiB per complete frozen record, including baseline results
- At most 32 saved previews, each at most 2 MiB; at most four in-flight preview requests per server
- At most 256 approved and 256 candidate immutable metric/version hash bindings in separate registries; neither contains raw inputs or actor data
- HTTP bodies at most 16 KiB; candidate policies at most 8 KiB, strict known fields and bounded collections

Expired records are pruned on every capture and preview request; expired data cannot be read even before the next pruning operation. Live records are not silently evicted to make room. When capture exceeds capacity/size or encounters an approved-version binding conflict, an otherwise approved publication remains publishable and its private runtime result reports `comparisonInput.state: unavailable` with a bounded reason. Only these explicit optional-capture failures degrade in this way: security denials, integrity errors and publication-marker/database failures still fail closed. Preview writes exceeding capacity fail atomically without partial policy bindings. No older record is offered as a substitute for missing frozen input. The HTTP host, database adapter and role/configuration authorities must still provide deployment-appropriate deadlines, rate limits and backup deletion controls; none is invented here.

Correction authorization capture indexes the exclusion audit and row evidence once per baseline aggregate. It removes row counterevidence within that aggregate before combining eligible fact IDs for the same metric, then retains the original correction order and full fact hashes. This avoids rescanning all baseline evidence for every corrected fact while preserving the existing reviewed-revision, cutoff and privacy rules. The deterministic regression counts actual array-member reads through the metrics engine and SQLite capture/reopen path; it establishes lookup growth at the tested synthetic scale, not a production latency budget.

## Synthetic verification

`apps/controls/test/policy-comparison.test.mjs` uses the actual metric engine and authenticated HTTP controls to cover exact restart/replay, inclusion/rank/value causes, correction exclusions, immutable policy versions, absence of activation/public leakage, current privacy redaction, future-correction cutoff handling, revocation at both awaited authority boundaries, absent/stale/thenable authority fences, integrity failures, expiry, strict input limits, concurrency and transactional capacity failures. `apps/pipeline/test/pipeline.test.mjs` proves actual pipeline capture, private snapshot-bound audit, restart replay, public projection separation, source-generation revocation, source lock ordering and successful public confirmation when private registry capacity is exhausted. `apps/controls/test/policy-preview-authority.test.mjs` exercises the versioned local cache, exact identity binding, expiry and synchronous revocation. No test fixture is real contribution or approval evidence.

`apps/controls/test/policy-capture-corrections.test.mjs` checks correction-capture growth, full receipt/hash persistence and replay, cutoff/review eligibility, mismatched metrics, row counterevidence, aggregate-local eligibility, repeated input receipts and indexed membership without custom iterator execution.

Required publication arithmetic and inclusion/exclusion persistence is separate: see [Required private aggregate explanations](required-aggregate-explanations.md). A preview becoming unavailable or expiring cannot remove that required record.
