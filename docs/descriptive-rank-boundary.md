# Descriptive metrics at the public boundary

Partial implementation evidence for #98. Engine policy validation already rejects contributor ranks for ratio, duration and descriptive-only definitions. The public projection now enforces the same restriction against the service's configured registry: an explicit `rank: true` or an omitted flag (the legacy ranked default) rejects the provider response. It does not silently change contradictory publication metadata into an unranked result. Eligible count metrics retain their existing ranked behavior.

This check runs before public pagination, conditional responses and JSON/CSV export. A previously valid ETag cannot turn a later contradictory provider response into a cached success. Browser board/export parsers separately reject descriptive ranking descriptors and numeric row ranks, including a numeric rank accompanied by a null descriptor. Legitimate unranked diagnostics, values, sample counts and censoring remain available. Registry-defined descriptive raw activity is subject to the same restriction; synthetic rank-focused journeys use a rank-eligible metric rather than overriding its definition.

Tests exercise `pr_accepted_rate`, `review_wait` and `active_periods`, explicit false versus true/omitted flags, profiles and both export formats, client parsing, configured-registry semantics and conditional reads. Existing ranking, privacy, cursor, evidence and card assertions remain in the fixture journeys.

This does not complete #98: the engine participation helper still needs frozen publication, privacy-safe API and remote UI integration. Organization-wide newcomer certification cannot be inferred from a repository-only frozen dataset. Complete-history evidence and selected calendar-week denominators remain required for any certified newcomer or normalized participation claim. Existing sample/censoring diagnostics are preserved; no source receipt, contributor approval or production evidence is invented.
