# Protected account and administration UI

`/account` and `/admin` (including a trailing slash) always load authenticated controls UI, even when public prototype mode is selected. The browser reads the same-origin `/controls/session`; it cannot select an account or grant itself a role. Cookies remain HttpOnly, CSRF values stay in memory, requests use no-store and reject redirects, and mutations include the server-issued CSRF token. The server remains the authority for every operation. Public API origin configuration is never used for private traffic. Production routing must serve the UI and proxy `/controls/*` on the approved HTTPS origin with no caching of authenticated responses.

Configure the controls server's `loginSuccessPath: '/account'` when hosting this UI. The default backend callback lands on its JSON session endpoint, so without that option the user must return to `/account` after login. No identity-provider registration, credentials, permission grant or production deployment is supplied by the UI.

Errors never fabricate a receipt. A 409 requires reload; there is no automatic mutation retry. A mutation followed by failed readback reports the readback error and does not claim refreshed state; reload receipts before deciding whether to retry. Hidden or superseded requests cannot restore private content. Responses have an eight-second deadline and a two-megabyte decoded-body limit. Forms escape text through React; source text is not rendered as executable HTML. No response/session is persisted in local storage. Optional profile changes and controls data do not alter upstream GitHub content.

## Validation

`apps/web/test/controls-client.test.ts` checks fail-closed sessions, review authority, credential routing and CSRF boundaries. `apps/web/browser/controls.spec.ts` checks anonymous denial (including prototype mode), saved profile readback and mutation receipt, denied admin access, independent review and private-state clearing on revoked authority, with axe checks on anonymous and account screens. Operator browser tests check version/digest/approval binding across preview, approval and activation; single-metric disable preserves policy; self-approval, stale proposals and malformed JSON are rejected. Browser responses are explicitly mocked controls responses: these are UI contract tests, not live OAuth, production authorization or real contributor evidence. Existing controls backend tests separately cover storage and authorization.

Run `npm run build`, `npm run test:browser -- --grep 'anonymous account|account loads|admin denies|expired authority'`, and `node --test apps/web/test/controls-client.test.ts`. Accepted evidence owners can separately opt into editorial spotlight review; the private nomination queue supports withdrawal and independent accept/reject decisions with an explicitly public selection explanation. Public spotlight selection is not a metric ranking.

Screen-reader, real-device and affected-owner acceptance remain outstanding. No issue is closed solely by these screens.

`apps/web/browser/amendment.spec.ts` verifies exact amendment payload and CSRF, saved-field readback, pending-state reload after success, removal of accepted-only nomination, and a stale-version conflict without automatic retry. Amendment reasons/history remain protected; source/scope/attribution can become public after acceptance. This is additional UI coverage for #55/#60/#122, not live source or policy acceptance.
